Testers spend their days hunting for the one input that breaks a rule. Logic tells you exactly what that input looks like, so you can build it on purpose instead of hoping to stumble on it.

Anatomy of a violation

A contract “if P then Q” is violated by any case where:

  • the premise P is true (the rule applies), and
  • the conclusion Q is false (the rule was not honoured).

Cases where P is false do not violate anything, no matter what Q is.

An example from a code review

Requirement: “if the order total is over 1,000 baht, shipping is free.” Suppose the test data shows an order of 1,500 baht that was charged shipping. The premise (over 1,000) is true and the conclusion (free shipping) is false, so this is the counterexample that proves the code wrong. An order of 500 baht charged shipping is not a violation, because the rule never applied.

Your task

Set the inputs P and Q so that P → Q is false. There is exactly one correct combination. Before you toggle anything, decide what P and Q must each be, and then confirm it on the circuit.

Key idea: a counterexample to an implication is a true premise paired with a false conclusion.
