Augustus De Morgan noticed that negation “pushes through” AND and OR, swapping one for the other. It is the most used law in everyday programming logic.

The two laws

¬(P ∧ Q) ≡ ¬P ∨ ¬Q
¬(P ∨ Q) ≡ ¬P ∧ ¬Q

To apply either law: negate each part, then swap AND with OR (or OR with AND). The parentheses go away.

Why it is true

Look at the table from the previous lesson. ¬(P ∧ Q) was false only when both P and Q were true. ¬P ∨ ¬Q is false only when both ¬P and ¬Q are false, which again happens only when P and Q are both true. Same rows, so equivalent.

In code

// before
if (!(user.isActive && user.hasLicense)) { deny(); }

// after (De Morgan)
if (!user.isActive || !user.hasLicense) { deny(); }

Both mean “deny unless the user is active and licensed”. The second form reads as a list of reasons to deny, which is often clearer.

Common mistakes

  • Negating the variables but forgetting to swap AND and OR.
  • Swapping the connective but forgetting to negate the variables.
Key idea: negate everything inside, flip AND to OR (or OR to AND).
