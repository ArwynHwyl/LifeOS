Negating a condition is one of the easiest places to introduce a bug. Before learning the rule that governs it, let us look at the truth pattern of ¬(P ∧ Q) directly.

Build the pattern

First, remember that P ∧ Q is true in only one row (both true). Negation flips every row, so ¬(P ∧ Q) is false in that single row and true in the other three.

P  Q | P ∧ Q | ¬(P ∧ Q)
T  T |   T   |    F
T  F |   F   |    T
F  T |   F   |    T
F  F |   F   |    T

Notice that the output is false in exactly one row: the one where P and Q are both true.

A plain-language reading

“It is not the case that both hold” means at least one of them fails. In software: “not (isAdult and hasConsent)” is true for a minor with consent, an adult without consent, and a minor without consent.

Explore

Toggle P and Q on the circuit and record when the output turns on. As you do, ask yourself: is there a simpler expression using only NOT on the individual variables that lights up in the same rows? You will name it in the next lesson.

Key idea: ¬(P ∧ Q) is false only when P and Q are both true.
