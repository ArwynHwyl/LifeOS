Explaining a circuit is one skill. Steering it to a target is another, and it is exactly what a tester does when writing a case that reaches a particular branch of code.

The goal

Set the inputs P, Q, and R so that (P ∧ Q) ∨ ¬R evaluates to true.

A method that always works

  1. Look at the outermost connective. Here it is OR, so one true branch is enough.
  2. Pick the cheaper branch. Making ¬R true only needs R = F. Making P ∧ Q true needs two inputs to be T.
  3. Set the inputs for that branch and check the result by hand.

Working backwards from the desired output like this is much faster than trying all eight rows.

How many solutions are there?

Because either branch can succeed, there are several correct settings. R = F works no matter what P and Q are. If R = T you need both P and Q to be true instead. Five of the eight rows make the expression true.

Key idea: to make an OR true, satisfy any one branch. To make an AND true, satisfy every branch.

Try one solution from each family and read the circuit to confirm which branch is carrying the current.
